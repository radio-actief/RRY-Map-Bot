              Region CLI reference — tree, flood behaviour, inspection
            
            

              

                Short guide for Belgian repeaters. Authoritative syntax and
                notes:
                MeshCore cli_commands.md — region management
                  →. Use be / be-* / UN/LOCODE city
                codes from this page for Belgium.
              

              

                Flood forwarding:
                region load vs allowf /
                denyf
              

              

                allowf / denyf control whether traffic for that
                exact region name may use flood forwarding.
                That is separate from building the tree with
                region put or interactive region load.
              

              
    
                
  • 
                  region load (interactive): a
                  line may end with F to enable flood for that node
                  while loading the tree.
                
    • 
                
  • 
                  region allowf /
                    region denyf: set flood forwarding per region name once regions exist —
                  the Allow / deny policy table on this page generates these
                  lines only (not the region load
                  F suffix).
                
    • 
              

              

                Full syntax and behaviour:
                MeshCore cli_commands.md — region management
                  →.
              


              

                Practice: region & message scope
              

              

                Naming and scopes follow MeshCore region semantics (see upstream
                docs). This configurator targets Belgium only —
                use the generated be tree (provinces such as
                be-vbr or be-bru, cities as UN/LOCODE
                such as beleu).
              

              
    
                
  • 
                  Follow international conventions: country code, province, city
                  (UN/LOCODE); optional broader “area” codes where used.
                
    • 
                
  • 
                  Messages without a scope are often tied to
                  wildcard * — keep allowf * for
                  compatibility while you add specific regions (see MeshCore
                  docs).
                
    • 
                
  • 
                  Configure at least your province layer and
                  allowf for scopes you want to forward; border
                  repeaters can add neighbouring provinces (same idea as the
                  neighbour lists in this tool).
                
    • 
                
  • 
                  Some firmware builds recommend a reboot after
                  region changes — follow your device notes.
                
    • 
              

              

                For Belgium, rely on the be-* structure from the
                generator and command block on this page.
              


              

                

                  
                    

                      Command
                      Description
                    

                  
                  
                    

                      region
                      
                        Show region tree and flood flags (older firmware: serial
                        dump only).
                      
                    

                    

                      region put <name> [parent]
                      
                        Create a region; optional parent (defaults to wildcard).
                      
                    

                    

                      region remove <name>
                      
                        Remove a leaf region (no children; remove children
                        first).
                      
                    

                    

                      region allowf <name>
                      
                        Allow flood forwarding for this exact
                        region name. allowf *: behaviour for
                        ROUTE_TYPE_FLOOD packets
                        without region transport codes (see
                        below).
                      
                    

                    

                      region denyf <name>
                      
                        Deny flood forwarding (default for new regions).
                        denyf *: drop those untagged flood packets.
                      
                    

                    

                      region home <name>
                      
                        Set home region (often shown with ^ in the
                        tree).
                      
                    

                    

                      region get <name>
                      Show details for one region.
                    

                    

                      region list allowed
                      
                        List regions that allow flood (serial-only; firmware ≥
                        1.12).
                      
                    

                    

                      region list denied
                      
                        List regions that deny flood (serial-only; firmware ≥
                        1.12).
                      
                    

                    

                      region save
                      Persist region changes to flash.
                    

                    

                      region load
                      
                        Start interactive multi-line mode: tree by indentation,
                        optional F suffix per line for flood on
                        that node. Blank line ends session. Empty name not
                        usable remotely.
                      
                    

                  
                

              


              

                Example configuration (Belgian codes)
              

              
CLI input

              
region put be
region put be-vbr be
region put be-vov be
region put beleu be-vbr
region allowf be
region allowf be-vbr
region allowf beleu
region save

              
Resulting tree (region)

              
* F
 be F
  be-vbr F
   beleu F
  be-vov

              
    
                
  • 
                  * is the wildcard root; F after a
                  name means flood is allowed for that region.
                
    • 
                
  • 
                  be-vov (example East Flanders) has no
                  F here — flood denied unless you add
                  allowf.
                
    • 
                
  • 
                  be, be-vbr, and beleu
                  allow flood in this sketch.
                
    • 
              


              

                The wildcard region (*)
              

              

                The * region controls packets that use
                ROUTE_TYPE_FLOOD
                without region transport codes:
              

              
    
                
  • 
                  region allowf * — forward those untagged flood
                  packets (common default).
                
    • 
                
  • 
                  region denyf * — drop all untagged flood packets.
                
    • 
              


              
Important behaviour

              
Flat matching (no routing hierarchy)

              

                Despite parent-child display in the tree,
                matching is flat: a packet tagged
                beleu does not automatically match
                be-vbr for routing, even if be-vbr is
                the parent of beleu in the tree.
              

              

                The parent argument to region put mainly affects:
              

              
    
                
  • Tree layout in region output;
    • 
                
  • 
                  Removal rules (cannot remove a node that still
                  has children);
                
    • 
                
  • region get output.
    • 
              

              
It does not change packet routing logic.


              
Default deny (flood)

              

                New regions start with flood denied. Use
                region allowf <name> (or a line ending in
                F during region load) to allow flood
                forwarding for that name.
              


              
Persistence

              

                Regions are stored on device flash (e.g. under
                /regions2). Run region save after
                changes — otherwise they are lost on reboot.
              


              
Firmware memory limits

              
    
                
  • 
                  At most 32 regions per repeater
                  (MAX_REGION_ENTRIES).
                
    • 
                
  • Region names up to 30 characters.
    • 
                
  • 
                  16 cached transport keys
                  (MAX_TKS_ENTRIES).
                
    • 
              


              
Practical use cases

              
Geographic scoping (Belgium)

              
region put be
region put be-vbr be
region put be-vov be
region allowf be-vbr
region save

              

                This repeater only allows flood for be-vbr; traffic
                tagged for be-vov does not burden this node. Add
                provinces and cities from the Found codes section as needed.
              


              
Topic-style channels

              
region put emergencies
region put chat
region put weather
region allowf emergencies
region allowf weather
region save

              

                Forward only selected topics (here: emergencies and weather, not
                general chat). Use names agreed within your mesh community.
              


              
Private networks

              
region put $company
region allowf $company

              

                Private regions ($name) need keystore support;
                firmware may still be incomplete — check MeshCore source and
                release notes.
              


              
Limitations

              
    
                
  • 
                  16-bit transport codes — collisions are
                  theoretically possible; HMAC makes deliberate collisions
                  infeasible.
                
    • 
                
  • 
                  No hierarchical matching — parent-child is
                  cosmetic (see flat matching above).
                
    • 
                
  • 
                  Private regions ($name) —
                  keystore not fully complete on all builds; check firmware.
                
    • 
                
  • 
                  Static configuration — per repeater via CLI;
                  no automatic discovery or sync.
                
    •
